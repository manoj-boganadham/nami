# Nami — Functional Requirements Document (v2)

**Project:** Nami Personal Finance Assistant  
**Owner:** Personal use  
**Version:** 2.0  
**Date:** 2026-05-24

---

## 1. Overview

Nami v2 introduces the "Log Book" tab to the web dashboard. This feature allows the user to inspect the list of raw ingested messages, see their processing status (processed vs pending) and parse status (successful vs failed), and manually trigger reprocessing on demand.

---

## 2. Updated System Flows

### 2.1 Raw Message Inspection Flow
1. User opens dashboard and switches to the "Log Book" tab.
2. Dashboard queries the API endpoint `GET /api/raw_messages` to retrieve raw SMS records.
3. User can filter messages by status: All, Pending, Processed, Parse Failed.
4. User can search messages by matching text.

### 2.2 Manual Reprocessing Flow
1. User identifies a pending or parse-failed message in the "Log Book" list.
2. User clicks the "Reprocess" action button next to the message.
3. Dashboard sends a POST request to `/api/raw_messages/{id}/reprocess`.
4. The system runs the regex extractor on that message:
   - If an amount is successfully parsed: creates a transaction (or updates it if already exists), and marks the raw message as `processed = true`, `parse_failed = false`.
   - If parsing fails: marks the raw message as `processed = true`, `parse_failed = true`.
5. The view refreshes immediately to display the updated status.

## 3. Functional Requirements

### 3.1 Raw Messages API

| ID | Requirement |
|---|---|
| FR-31 | System SHALL expose a `GET /api/raw_messages` endpoint |
| FR-32 | Endpoint SHALL support status filtering via query parameter `?status=all|pending|processed|failed` |
| FR-33 | Endpoint SHALL support keyword search via query parameter `?search=keyword` |
| FR-34 | Endpoint SHALL return a list of raw messages sorted by `received_at` descending |
| FR-35 | System SHALL expose a `POST /api/raw_messages/{id}/reprocess` endpoint |
| FR-36 | Reprocess endpoint SHALL attempt regex extraction on the specified message and update the database |

### 3.2 Dashboard (UI Navigation & Log Book View)

| ID | Requirement |
|---|---|
| FR-37 | Dashboard SHALL expose a tab selector in the header: "The Chart Room" (v1 analytics) and "The Log Book" (v2 raw messages) |
| FR-38 | Log Book view SHALL display raw messages in a responsive grid/table, listing ID, Message Text, Status, Date Received, and Actions |
| FR-39 | Status columns SHALL display color-coded badges: Green for Processed, Gold for Pending, and Red for Parse Failed |
| FR-40 | Log Book view SHALL provide dropdown filter options for status (All, Pending, Processed, Parse Failed) and a search input for message text |
| FR-41 | Each message row SHALL display a "Reprocess" button if status is Pending or Parse Failed |
| FR-42 | Clicking "Reprocess" SHALL call `/api/raw_messages/{id}/reprocess` and update the local state without requiring a page reload |
