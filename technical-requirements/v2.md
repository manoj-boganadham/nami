# Nami — Technical Requirements (v2)

This document describes the technical specifications for the new Raw Messages tab and reprocessing feature in **Nami v2**.

---

## 1. Backend Specifications

### 1.1 Database Access
- No database schema modifications are required. The existing `raw_messages` table already contains the necessary columns (`processed`, `parse_failed`, `message`, `received_at`).

### 1.2 Endpoints

#### 1.2.1 Get Raw Messages
- **Endpoint:** `GET /api/raw_messages`
- **Query Parameters:**
  - `status`: Optional string. Value must be one of `all` (default), `pending`, `processed`, `failed`.
    - `pending`: `processed == False`
    - `processed`: `processed == True AND parse_failed == False`
    - `failed`: `processed == True AND parse_failed == True`
  - `search`: Optional string. Case-insensitive search on the raw message text.
- **Response (200 OK):**
  ```json
  [
    {
      "id": 5,
      "message": "Paid ₹1500 to Store A",
      "received_at": "2026-05-24T00:00:00Z",
      "processed": true,
      "parse_failed": false
    }
  ]
  ```

#### 1.2.2 Reprocess Specific Message
- **Endpoint:** `POST /api/raw_messages/{id}/reprocess`
- **Process Logic:**
  1. Fetch `RawMessage` by ID. If not found, return `404 Not Found`.
  2. Parse the message body using `extract_amount(message)` from `services/transaction_generator.py`.
  3. If an amount is extracted:
     - Check if a `Transaction` referencing this `raw_message_id` already exists.
     - If yes: update its `amount` and `timestamp`.
     - If no: insert a new `Transaction` with `category = null`, `description = raw_message.message`, `timestamp = raw_message.received_at`.
     - Set raw message `parse_failed = false`.
  4. If no amount is extracted:
     - Delete any existing `Transaction` associated with this `raw_message_id` (if applicable).
     - Set raw message `parse_failed = true`.
  5. Set raw message `processed = true`.
  6. Commit changes.
- **Response (200 OK):**
  ```json
  {
    "status": "success",
    "message": "Message reprocessed",
    "raw_message": {
      "id": 5,
      "processed": true,
      "parse_failed": false
    },
    "transaction_created_or_updated": true
  }
  ```

---

## 2. Frontend Specifications

- **Routing / Tab State:** Add an active tab state (`activeTab` as `"chart"` or `"logbook"`) inside `App.tsx`.
- **View Switching:** Renders the dashboard analytics when `activeTab === "chart"`, and the new raw messages grid when `activeTab === "logbook"`.
- **Status Filter Logic:** Uses a stateful drop-down in the Log Book view to bind the `GET /api/raw_messages` status query param.
- **Reprocess Handler:** Binds clicking the Reprocess button to make a fetch request `POST /api/raw_messages/{id}/reprocess`, updating stats and messages.
