

# Nami — Technical & UI Requirements (v1)



## Overview

Nami is a personal finance tracking system that captures debit/spend SMS messages from an iPhone, processes them into structured transactions, and presents spending analytics via a web dashboard. The user can categorize transactions from the dashboard or via notification reply. The system is designed for single-user, local/private network deployment, with a focus on privacy, speed, and ease of use. No AI-based auto-categorization is performed; all categorization is manual for accuracy.

---




## 1. Message Ingest API

- **Endpoint:** `POST /api/messages`
- **Stack:** Python, FastAPI
- **Input:** Plain text or JSON body containing the raw SMS message string
- **On receipt:**
  - Attach a UTC timestamp
  - Save to `raw_messages` table:
    - `id` (auto-increment)
    - `message` (original SMS text)
    - `received_at` (UTC datetime)
    - `processed` (boolean, default false)
    - `parse_failed` (boolean, default false)
- **Response:** `201 Created` with saved record JSON, or `400` if message body is empty
- **Security:** Requires static API key in `X-API-Key` header

---




## 2. Transaction Generation (Cron Job)

- **Script:** `generate_transactions.py` (invoked by cron)
- **Logic:**
  - Query all `raw_messages` where `processed = false`
  - For each message:
    - Extract INR amount using regex (supports: `₹500`, `Rs 500`, `Rs. 1,200`, `500 rupees`, `paid 300`, `spent 450`)
    - If amount found: create a record in `transactions` table with `amount`, `raw_message_id`, `timestamp` (from raw message), `category = null`
    - If amount not found: mark message as `processed = true`, `parse_failed = true` and skip
  - Mark all attempted messages as `processed = true`
- **Config:** Cron schedule is set in `.env` (default: `0 23 * * *`)

---



## 3. Categorization

- **API:** `PATCH /api/transactions/:id` to update category
- **Categories:** Food, Transport, Shopping, Health, Utilities, Entertainment, Other
- **Dashboard:**
  - Visually distinguish uncategorized transactions (muted row + tag)
  - Inline category picker on transaction row tap/click
- **Notification (optional):**
  - When a new transaction is generated, send a notification (push/Telegram/WhatsApp) with transaction details and category options
  - User replies with number or category name; system updates transaction via PATCH endpoint

---



## 4. Dashboard (UI Requirements)

- **Stack:** FastAPI backend, vanilla JS or React frontend
- **Endpoints:**
  - `GET /dashboard` — Main dashboard view
  - `GET /api/transactions` — List transactions (supports `?date=`, `?from=&to=`)
  - `PATCH /api/transactions/:id` — Update transaction category
  - `GET /api/stats` — Aggregated stats for a date range
- **Features:**
  - Loads with today's transactions by default
  - Date range presets: Today, Last 7 Days, Last 30 Days, Custom
  - Total spend for selected range
  - Category-wise spend breakdown (bar/donut chart)
  - Daily spend trend (bar chart)
  - Transaction list grouped by day, showing amount, description, category
  - Flag and highlight transactions above threshold (default ₹2,000)
  - Visually highlight uncategorized transactions
  - Inline category picker on transaction row
  - Light/dark theme toggle (preference saved in localStorage)
  - Show count of uncategorized transactions as a prompt

## 5. Database Schema (SQLite)

### `raw_messages`
| Column | Type | Notes |
|---|---|---|
| id | INTEGER | PK, autoincrement |
| message | TEXT | Raw SMS content |
| received_at | DATETIME | UTC, set on insert |
| processed | BOOLEAN | Default false |
| parse_failed | BOOLEAN | Default false |

### `transactions`
| Column | Type | Notes |
|---|---|---|
| id | INTEGER | PK, autoincrement |
| raw_message_id | INTEGER | FK → raw_messages.id |
| amount | REAL | Extracted INR amount |
| category | TEXT | Null until user assigns |
| timestamp | DATETIME | Copied from raw_message.received_at |
| created_at | DATETIME | UTC, set on insert |

## 6. Configuration

All configurable values in a `.env` file:

```
API_KEY=...  # For ingest endpoint
LARGE_SPEND_THRESHOLD=2000
DATABASE_PATH=./finance.db
CRON_SCHEDULE=0 23 * * *
PORT=8000
```

## 8. Out of Scope

- AI-based auto-categorization (user assigns manually)
- Multi-user support or authentication beyond API key
- Budget limits or savings goals (future)
- iOS app — automation via iPhone Shortcuts only
