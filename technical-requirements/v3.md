# Nami — Technical Requirements (v3)

This document outlines the database changes, migration pathways, API modifications, and processing rules for **Nami v3**.

---

## 1. Database Schema Migration

To support custom ingestion values and payment channels:
- **`raw_messages` table:**
  - Add `category`: `TEXT`, NULLABLE.
  - Add `mode_of_payment`: `TEXT`, NULLABLE.
- **`transactions` table:**
  - Add `mode_of_payment`: `TEXT`, NULLABLE.

### Migration Execution
Since SQLite lacks automated migration tools by default, the database initialization script `db/init_db.py` will run manual migration statements on startup.
- It will inspect the tables using PRAGMA instructions:
  - `PRAGMA table_info(raw_messages)`
  - `PRAGMA table_info(transactions)`
- If `category` or `mode_of_payment` are missing from the column list, it will execute:
  - `ALTER TABLE raw_messages ADD COLUMN category TEXT`
  - `ALTER TABLE raw_messages ADD COLUMN mode_of_payment TEXT`
  - `ALTER TABLE transactions ADD COLUMN mode_of_payment TEXT`

---

## 2. Ingestion & Processing Logic

### 2.1 Ingestion Model
The `POST /api/messages` (and `/messages`) JSON payload parsing schema is updated to:
```json
{
  "message": "Required string",
  "category": "Optional string or null",
  "modeOfPayment": "Optional string or null"
}
```

### 2.2 Processing Pipeline
In `services/transaction_generator.py` and `/api/raw_messages/{id}/reprocess`:
- When creating a new `Transaction` record, pre-fill its columns with values from the parent `RawMessage` model:
  - `category`: If `raw_message.category` is in the allowed list (`Food`, `Transport`, etc.), copy it. Otherwise, set it to `null`.
  - `mode_of_payment`: Copy `raw_message.mode_of_payment` directly.

---

## 3. Transaction API Extensions

### 3.1 Update Transaction
- **Endpoint:** `PATCH /api/transactions/{id}`
- **Payload Schema:**
  ```json
  {
    "category": "Optional string or null",
    "description": "Optional string or null",
    "mode_of_payment": "Optional string or null"
  }
  ```
- **Validation:**
  - `mode_of_payment` must be one of: `UPI`, `Card`, `Cash`, `Net Banking` (or empty/null to clear).

### 3.2 List Transactions
- **Endpoint:** `GET /api/transactions`
- **Output:** Returns `mode_of_payment` in the transaction JSON object:
  ```json
  {
    "id": 1,
    "amount": 500.0,
    "category": "Food",
    "description": "Lunch spent",
    "mode_of_payment": "UPI",
    ...
  }
  ```
